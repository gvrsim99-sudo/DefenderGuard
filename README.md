# DefenderGuard — панель Microsoft Defender для Windows

Русскоязычное настольное приложение на .NET 8 / Windows Forms. **Проверки и антивирусный движок выполняет установленный Microsoft Defender Antivirus** через `MpCmdRun.exe` и модуль PowerShell Defender. Приложение не содержит собственной сигнатурной базы и не является независимым антивирусным движком.

## Возможности

- Показывает состояние антивируса и защиты в реальном времени, версию сигнатур и последнюю проверку из `Get-MpComputerStatus`.
- Запускает быструю/полную проверки Microsoft Defender, проверку выбранной папки и файлов, а также съёмных USB-накопителей.
- Перед проверками, запускаемыми DefenderGuard, по умолчанию создаёт или находит системную точку восстановления Windows не старше 24 часов. Настройку можно отключить; если точку не удалось подготовить, ручная проверка просит явное решение продолжать без неё, а плановая и WMI-проверки пропускаются.
- Проверяет распространённые точки автозапуска: пользовательскую и общую папки Startup и ключи `Run`/`RunOnce` для HKCU/HKLM в 32- и 64-битных представлениях реестра.
- Проверяет доступные файлы-образы активных процессов на диске. Необязательный WMI-монитор ставит новые версии образов запущенных процессов в очередь проверки Defender, пока приложение открыто; очередь ограничена 100 файлами.
- Вкладка **«Эвристика»** оценивает стандартные записи автозагрузки, команды из Run/RunOnce и доступные образы активных процессов по объяснимому набору признаков: закодированный запуск, скрытое окно, обход Execution Policy, сочетание сценарного интерпретатора с сетевой загрузкой, сценарные/исполняемые файлы в пользовательских областях и некоторые атрибуты файла. Список показывает причину каждого сигнала, уровень и балл; новые события WMI тоже добавляются в текущую сессию. Для файлового сигнала кнопка **«Разобрать и действовать»** показывает путь и текущий SHA-256, позволяет открыть файл, повторно проверить его Microsoft Defender и после явного подтверждения либо добавить точный SHA-256 в локальный белый список, либо поместить файл в локальный карантин; можно также оставить сигнал без изменений. Автоматических действий нет.
- Предоставляет отдельный **локальный карантин файлов**: пользователь выбирает файлы, приложение копирует их в хранилище с нейтральным расширением `.qtn`, сравнивает SHA-256 и удаляет исходник только после проверки копии. При сбое оригинал сохраняется.
- Перед восстановлением файл проверяется Microsoft Defender и сверяется с исходными длиной и SHA-256. Если исходный путь занят, файл возвращается под новым именем без перезаписи. Безвозвратное удаление из локального карантина требует отдельного подтверждения.
- Открывает встроенную «Защиту Windows» для истории обнаружений и **собственного карантина Microsoft Defender**. Автоматически помещать обнаружения Defender в локальный карантин DefenderGuard не пытается.
- Запускает ручное обновление сигнатур и настраивает ежедневную или еженедельную быструю проверку через Windows Task Scheduler.
- Вкладка **«Анализ файлов»** локально считает SHA-256, показывает совпадения с пользовательскими чёрным/белым списками, отображает объяснимые эвристические сигналы и запускает проверку выбранных файлов Microsoft Defender. До 100 файлов за один запуск; DefenderGuard не загружает образцы во внешний сервис. Собственные облачная защита и передача образцов Microsoft Defender зависят от настроек Windows.
- В **«Параметры»** есть явно запускаемая самозащита: установка приложения в `Program Files`, ACL каталога, видимая служба Windows и задача входа пользователя; служба сверяет SHA-256 EXE и запрашивает повторный запуск интерфейса после его завершения.
- Вкладка **«Сеть»** локально показывает текущие TCP-соединения, PID, доступный путь EXE, порт/адрес и объяснимые контекстные сигналы риска. Автообновление каждые 10 секунд выключено по умолчанию и работает только пока открыта вкладка.
- Блокировка доступна только после выбора соединения, направления и явного подтверждения. После UAC приложение создаёт сохраняемое точечное правило Windows Firewall: исходящее — EXE + удалённый IP + TCP-порт; входящее — EXE + IP источника + локальный TCP-порт. Можно удалить только правила группы DefenderGuard.

## Самозащита приложения

Самозащита **выключена до явного нажатия пользователем** кнопки установки в `Параметры`. Windows запросит UAC. После установки приложение:

1. Копирует `DefenderGuard.exe` в `%ProgramFiles%\DefenderGuard` и проверяет SHA-256 копии.
2. Настраивает каталог так, чтобы `SYSTEM` и `Administrators` имели полный доступ, а группа `Users` — только чтение и запуск. Контрольная сумма сохраняется в `%ProgramData%\DefenderGuardSelfProtection` с ограниченными ACL.
3. Создаёт видимую службу `DefenderGuard — самозащита`, работающую от `LocalSystem`, с автозапуском Windows и действиями восстановления после сбоя. Служба не взаимодействует напрямую с рабочим столом.
4. Создаёт видимую задачу `DefenderGuard_SelfProtection_UI`, запускающую пользовательский интерфейс в интерактивном сеансе при входе. Если интерфейс закрыт, служба просит Планировщик заданий запустить его снова; проверка выполняется с коротким интервалом, поэтому перезапуск может занять несколько секунд.
5. Сверяет исполняемый файл с защищённым SHA-256-манифестом при запуске службы, при уведомлениях файловой системы и периодически. При несоответствии задача запуска интерфейса отключается, а запись добавляется в `%ProgramData%\DefenderGuardSelfProtection\self-protection.log`. Файл автоматически не подменяется: проверьте «Историю защиты Windows» и переустановите приложение после выяснения причины.

Отключение доступно в том же разделе параметров и требует UAC. Оно останавливает и удаляет службу и задачу, а ACL папки сбрасывает к наследуемым разрешениям `Program Files`; сам EXE остаётся на диске. Обычное закрытие защищённого интерфейса блокируется сообщением с инструкцией отключить самозащиту. При выходе из Windows и завершении работы системы это ограничение не применяется.

## Важные границы безопасности

- Самозащита — **не абсолютная защита от завершения или модификации**: служба обычно перезапускает интерфейс после закрытия, но не предотвращает сам факт завершения процесса. Администратор компьютера сохраняет возможность остановить/удалить службу, изменить ACL и файлы или удалить задачу. Здесь нет драйвера ядра, Protected Process Light (PPL), скрытой службы, блокировки Диспетчера задач или защиты от вредоносной программы с административными правами.
- Служба работает от `LocalSystem`, но её задачи ограничены проверкой локального EXE и запуском заранее зарегистрированной пользовательской задачи; она не принимает сетевые команды и не использует IPC с GUI. Записи службы и Планировщика заданий видимы в соответствующих системных оснастках. Установка/отключение изменяют локальную конфигурацию Windows только после явного действия и UAC.
- QA-сборка для локальной проверки подписана самоподписанным сертификатом `CN=DefenderGuard Local QA`. Это не публичный сертификат доверенного издателя; для распространения требуется доверенная подпись издателя и метка времени.
- Release-кандидат дополнительно проверен на реальной Windows 10 x64: выполнены чистая установка и удаление, запуск/удаление службы самозащиты, задача Планировщика, Program Files и ProgramData, подписи EXE/Setup и запись деинсталлятора. Это не заменяет отдельную проверку на одноразовой чистой VM.
- Локальный карантин — обратимое хранилище файлов, которые пользователь явно выбрал на странице карантина или в результатах локального анализа, **не результат детектирования** и не защищённая служба/песочница. Перед перемещением из анализа приложение сверяет SHA-256 с хешем, зафиксированным при сканировании; при несовпадении файл не удаляется. Содержимое хранится без шифрования в профиле текущего пользователя; вредоносная программа с теми же правами пользователя может получить к нему доступ. Microsoft Defender остаётся основным движком защиты.
- Восстановление требует запуска DefenderGuard от имени администратора, чтобы перед возвратом вызвать проверку Microsoft Defender. Если Defender сообщает об угрозе/ошибке либо файл изменился, восстановление блокируется. Проверка не гарантирует обнаружение всех угроз; восстанавливайте только файлы, которым доверяете.
- Обнаруженные самим Defender угрозы и его карантин отдельно обслуживаются Windows. Используйте кнопку **«Открыть Историю защиты Windows»** для просмотра и восстановления таких объектов; DefenderGuard не читает и не изменяет внутреннее хранилище Defender.
- В папку Windows приложение запрещает помещение файлов в локальный карантин. Папки целиком, символические ссылки и другие reparse-point файлы не принимаются. Для системных файлов, ложных срабатываний Microsoft Defender и защищённых объектов используйте встроенную «Историю защиты».
- Сканирование автозагрузки охватывает только стандартные папки Startup и ключи Run/RunOnce; оно не инвентаризирует службы, драйверы, WMI-подписки, задания планировщика и другие способы закрепления.
- Проверка процессов и WMI-монитор сканируют файл-образ на диске, а не память, внедрение кода или поведение процесса, и не предотвращают запуск. В комплексном отчёте дополнительно снимается WMI-контекст `PID → ParentPID → EXE → командная строка` и цепочка до 5 уровней родителей; TCP-соединения связываются с процессом по PID того же сетевого снимка. Командная строка для сохранения отчёта ограничена 2000 символами. Защищённые/короткоживущие процессы могут быть пропущены. Защиту в реальном времени обеспечивает служба Microsoft Defender.
- Эвристический балл — не вероятность заражения и не вердикт Defender. Возможны ложные срабатывания и пропуски. Анализатор не оценивает память, цепочку родительских процессов или командную строку уже запущенного процесса; для live WMI-событий доступен только путь образа. Результаты отдельных запусков эвристики в текущей вкладке живут в памяти до закрытия приложения, а завершённая комплексная проверка сохраняется отдельно в структурированной истории; никакая эвристика сама по себе не вызывает блокировку, удаление или карантин.
- Сетевой анализ перечисляет активные TCP endpoints и локальные UDP endpoints (`Get-NetUDPEndpoint`) с PID/доступным путём процесса. UDP-строка показывает привязку локального сокета, но источник не сообщает удалённый peer, направление, содержимое или фактический поток пакетов. DNS-монитор по отдельному флажку читает только новые события 3008 из локального канала `Microsoft-Windows-DNS-Client/Operational`; он не импортирует историю, не включает и не перенастраивает журнал и хранит последние 500 записей только в памяти. Если журнал отключён/недоступен, UI показывает это; настройки Windows не меняются. PID клиента/путь процесса могут отсутствовать в событии и не подменяются PID системного процесса Event Log. Длинные/высокоэнтропийные DNS-метки и редкие типы запросов — только слабые объяснимые признаки, не вердикт. DoH/DoT, запросы напрямую к IP, кэширование, приложения со своим DNS-клиентом и отключённый журнал создают слепые зоны. Пакеты, TLS, память процесса и внешняя репутация не анализируются; нет автоматической блокировки UDP/DNS или изменения резолвера. TCP/Firewall остаётся отдельным ручным действием.
- Направление инициатора TCP автоматически не определяется: перед блокировкой пользователь выбирает входящее или исходящее правило. Правило действует для всех профилей Windows Firewall до удаления, может нарушить сетевую работу приложения и не гарантирует немедленное завершение уже существующей сессии. Для изменения запускается отдельный helper через запрос UAC — повышенно запускать всю панель не требуется. Правило применяется только если соответствующий профиль/политика Windows Firewall активен; групповая политика или сторонний firewall могут изменить результат. Автоматического блокирования нет, существующие сторонние правила не меняются.
- Пользовательские списки сопоставляют точный SHA-256 и сохраняются в `%LOCALAPPDATA%\DemoGuard\file-lists.json`. Чёрный список добавляет метку, но сам по себе не удаляет и не помещает файл в карантин. Белый список пропускает только эвристическую оценку в новой вкладке анализа; он **не** создаёт исключение Microsoft Defender и не меняет реестр исключений. Правило относится к точному содержимому файла, а не к имени или пути.
- Большой список файлов процессов и активное наблюдение могут увеличить нагрузку на диск/процессор; файлы передаются Defender последовательно. Обычный WMI-монитор работает только пока приложение открыто, требует доступной службы WMI и сам не устанавливает автозапуск.
- Для проверок Microsoft Defender, обновления, мониторинга процессов и восстановления используйте **«Запуск от имени администратора»**, если Windows требует повышенных прав. DefenderGuard не отключает Windows Security, не меняет исключения и не останавливает процессы.
- Создание точки восстановления поддерживается `Checkpoint-Computer` только на клиентских Windows (например, Windows 10/11), требует прав администратора и заранее включённой Защиты системы. Приложение не включает её и не меняет частотные ограничения Windows; не более одной новой точки за 24 часа, поэтому свежая системная точка используется повторно. Точка не является резервной копией личных документов и не гарантирует восстановление удалённой угрозы.
- События и результаты DefenderGuard записываются локально в `%LOCALAPPDATA%\DemoGuard\history.log`; сетевая сводка не отправляется во внешний сервис. Завершённая комплексная проверка также сохраняет сетевой снимок: до 750 TCP-соединений с PID/процессом/EXE/endpoint/сигналом, до 100 уже полученных DNS-событий и состояние профилей/правил Windows Firewall, доступных DefenderGuard. Для каждого TCP-соединения отчёт показывает контекст совпадения с правилами DefenderGuard по EXE и, при возможности, IP/порту; это корреляция, а не утверждение о направлении трафика. DNS в отчёте отражает только события, уже полученные включённым пользователем DNS-монитором; DefenderGuard не импортирует историю DNS автоматически. Завершённые комплексные проверки дополнительно сохраняются структурированно в `%LOCALAPPDATA%\DemoGuard\scan-history.json`: максимум 30 последних отчётов, до 500 эвристических сигналов и до 200 действий на отчёт. Для сохранённых сигналов можно заново вычислить SHA-256 и выполнить явное действие: открыть файл, повторно проверить его Microsoft Defender, добавить точный SHA-256 в локальный белый список, поместить файл в локальный карантин или оставить без изменений. Каждое действие сохраняется вместе со временем, `ReportId`, источником/объектом, актуальным SHA-256, результатом и кодом Defender, если он применялся. Сохранённый отчёт можно открыть из **«Отчёт проверки»**; после действий список отчётов в текущем сеансе обновляется без перезапуска приложения. Облачная защита и передача образцов самим Microsoft Defender зависят от его настроек Windows. Ни одна антивирусная проверка не гарантирует обнаружения всех угроз.

## Как пользоваться

1. Распакуйте архив в постоянную папку, например `%LOCALAPPDATA%\Programs\DefenderGuard`, и запустите `DefenderGuard.exe`.
2. Выберите нужный вид сканирования на главном экране. Для автозагрузки и активных процессов проверяются доступные файловые образы; это не анализ памяти.
3. Для просмотра объяснимых сигналов откройте **«Эвристика»** и запустите анализ автозагрузки и/или активных процессов. Чтобы добавлять события новых запусков, включите обычный монитор на главном экране; он активен, пока открыто приложение.
4. В **«Анализ файлов»** выберите образцы для проверки. В таблице видны пользовательские правила, эвристика и код ответа Defender; код 0 и отсутствие сигналов не являются гарантией безопасности. Выберите строку и добавьте её SHA-256 в чёрный или белый список.
5. В **«Параметры»** нажмите **«Установить самозащиту»**, внимательно прочитайте подтверждение и одобрите UAC. После установки запускается копия из `Program Files`; служба и задача видны в Windows. Для выхода нажмите **«Отключить самозащиту»** и подтвердите запрос UAC.
6. Если служба сообщает о несовпадении SHA-256, сначала проверьте Историю защиты и журнал самозащиты. Не восстанавливайте файл вслепую; отключите самозащиту с UAC и переустановите доверенную сборку.
7. В **«Параметры»** оставьте включённым создание/проверку точки восстановления перед проверками, если хотите такой барьер. Если Windows не разрешит создать точку, ручная проверка спросит, продолжать ли без неё; расписание и фоновая проверка продолжаться без точки не будут.
8. Чтобы вручную поместить файл в локальный карантин, выберите его в **«Анализ файлов» → «Результаты анализа»** и нажмите **«Поместить выбранный файл в карантин»** либо откройте **«Карантин файлов» → «Поместить выбранные файлы в карантин»**. Проверьте путь и подтвердите действие: после копирования и проверки SHA-256 исходный файл удаляется; если содержимое изменилось после анализа, перенос блокируется. Эвристические сигналы не перемещаются автоматически и не доказывают, что файл — вирус. Реальные обнаружения Microsoft Defender обрабатываются согласно настройкам самого Defender и доступны в его **«Истории защиты Windows»**. Для возврата из локального карантина нажмите **«Проверить и восстановить»**: Microsoft Defender проверит объект, затем восстановление продолжится только при успешном результате и совпадении SHA-256. Чтобы удалить файл из карантина и его запись, нажмите **«Удалить полностью»** и подтвердите действие. Это удаляет объект средствами Windows, но не обещает криминалистическое стирание блоков SSD/носителя.
9. Для расписания выберите частоту, день/время и нажмите **«Сохранить и применить»**. Перед перемещением EXE отключите задачу.

### Сетевая активность и блокировка

Откройте **«Сеть»** и нажмите **«Обновить сейчас»**. Вкладка **«UDP endpoints»** показывает локальные UDP-привязки и владельцев PID, если доступно; удалённый адрес и пакеты из этого снимка получить нельзя. Для TCP/UDP-снимков каждые 10 секунд включите соответствующий флажок; опрос приостанавливается, когда вкладка закрыта. Для мониторинга новых DNS-запросов отдельно включите флажок DNS. События 3008 из `Microsoft-Windows-DNS-Client/Operational` будут записываться в таблицу только пока открыта вкладка **«Сеть»**; прежняя история не загружается. Если журнал выключен, DefenderGuard не включает его автоматически. В таблице DNS запросы, ответы/статус и объяснимые эвристические подсказки; атрибуция клиентского PID/процесса зависит от данных конкретного события. Для ручной настройки журнала откройте **Просмотр событий → Журналы приложений и служб → Microsoft → Windows → DNS-Client → Operational → Включить журнал**; это отдельное изменение Windows, которое DefenderGuard не выполняет.

Для ручного TCP-блокирования выберите TCP-строку, проверьте путь EXE и объяснение сигнала, затем выберите направление правила. Подтвердите действие в приложении и запрос UAC Windows. Правила не создаются автоматически и не применяются к UDP/DNS. Вкладка **«Правила DefenderGuard»** перечисляет созданные приложением правила и позволяет удалять каждое отдельно.

## Сборка из исходников

На Windows с .NET 8 SDK:

```powershell
dotnet publish .\DemoGuard.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:EnableCompressionInSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o .\publish
```

Для полного release-контура используйте `Installer\Build-Release.ps1`: он выполняет Release-сборку с ошибками предупреждений, четыре регрессионных теста, self-contained single-file publish, компиляцию Inno Setup, подпись и обязательную проверку Authenticode. Режим `QA` использует локальный самоподписанный сертификат только для тестовой машины; режим `Production` требует доверенного сертификата/сервиса подписи и RFC 3161 timestamp.

Переносимые регрессионные тесты покрывают ScanReportStore, QuarantineStore, TCP/Firewall payload validation, UDP/DNS эвристики, ограничения источников, integrity check карантина и отказ при несовпадении SHA-256 после анализа. Реальная Windows-проверка дополнительно покрыла Inno Setup install/uninstall, службу и задачу самозащиты, Program Files/ProgramData и Windows Defender. Отдельная одноразовая чистая VM для финальной проверки ещё не использовалась.

Основной результат — автономный `DefenderGuard.exe` для Windows x64. Microsoft Defender и Windows PowerShell являются системными компонентами Windows и не встраиваются в EXE. WMI, Windows Service hosting и Event Log API поставляются NuGet-зависимостями `System.Management`, `Microsoft.Extensions.Hosting.WindowsServices` и `System.Diagnostics.EventLog`.
